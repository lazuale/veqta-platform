# Организации и каталог спецодежды

Справочники находятся в PostgreSQL. Добавление записей, изменение названий и отключение выполняются через штатный Django Admin, без изменения кода и миграций. После чистой установки оба справочника пусты.

## Доступ

Откройте `/admin/` на адресе своего контура и войдите учётной записью администратора. Для доступа к Admin нужен признак «Статус персонала». Сам по себе он не даёт прав на справочники.

| Действие | Разрешение Django |
|---|---|
| Читать организации в Admin | `workwear.view_organization` |
| Добавлять организации | `workwear.add_organization` |
| Менять названия, связывать с 1С, разрешать заявки | `workwear.change_organization` |
| Удалять неиспользуемые организации | `workwear.delete_organization` |
| Читать каталог в Admin | `workwear.view_workwearitem` |
| Добавлять позиции | `workwear.add_workwearitem` |
| Менять позиции | `workwear.change_workwearitem` |
| Удалять неиспользуемые позиции | `workwear.delete_workwearitem` |

Назначайте разрешения через стандартные группы Django. Аналитику достаточно прав Workwear из [workwear.md](workwear.md): создание заявки не разрешает редактировать справочники. Пользователь только с правом просмотра видит формы Admin без возможности сохранить изменения. Сотрудники, заявки, назначения и журнал Workwear не зарегистрированы для редактирования в Admin.

## Создание организации

1. В разделе Workwear откройте «Организации» → «Добавить».
2. Введите отображаемое наименование.
3. Если известен `orgExtId` из 1С, укажите его в поле «Идентификатор 1С». Это ключ организации, а не GUID сотрудника или подразделения. Регистр букв не учитывается; идентификатор сохраняется в нижнем регистре. Пробелы внутри него не допускаются.
4. Чтобы организация появилась при создании заявки, включите «Разрешено создавать заявки». При отсутствии этого признака импорт сотрудников разрешён, создание новых заявок запрещено.
5. Сохраните запись. После этого можно загрузить сотрудников по [import_1c.md](import_1c.md).

Можно начать с импорта: неизвестная организация создаётся по `orgExtId` с запрещённым созданием заявок. Затем найдите её в Admin, проверьте поле «Последнее название из 1С» и разрешите заявки. Не создавайте вторую запись для уже принятого идентификатора.

Если организацию создали вручную без идентификатора, перед первым импортом укажите правильный `orgExtId`. Импорт не связывает записи автоматически по названию. При совпадении названия с несопоставленной старой записью приём останавливается и просит заполнить её идентификатор. При повторном приёме той же последней выгрузки данные не меняются; связывание старых записей должно быть выполнено до следующей новой выгрузки.

Идентификатор 1С можно задать один раз. После сохранения непустого значения заменить или очистить его нельзя. Два разных идентификатора с одинаковыми названиями остаются разными организациями. Сотрудник одного GUID не переносится в другую организацию; изменение его `orgExtId` отклоняет весь импорт.

## Добавление позиции

1. Откройте «Позиции спецодежды» → «Добавить».
2. Задайте уникальный код и наименование. Код после создания неизменяем.
3. Введите категорию. Это обычное название группы позиций, без фиксированного перечня в программе. Для одной группы используйте одинаковое написание.
4. Укажите срок в календарных днях: целое число от 1 до 32767. Например, 365 и 730 сохраняют прежний смысл. Приложение не переводит месяцы в дни и не выбирает срок по названию.
5. Установите порядок отображения: меньшее число показывается раньше. Включите «Активна» и сохраните.

Новая активная позиция доступна при следующей загрузке интерфейса Workwear. Количество записей справочника не фиксировано. Технический предел одной заявки остаётся прежним: до 1000 сотрудников и до 30 разных позиций у сотрудника. При большом каталоге матрица показывает позиции страницами.

Для первоначального массового заполнения можно использовать CSV-команду из [import_1c.md](import_1c.md). Она не заменяет редактирование через Admin и не перезаписывает отличающиеся записи.

## Изменения и история

| Изменение | Результат |
|---|---|
| Новое отображаемое название организации | Новые заявки получают новое название. Названия в прежних заявках сохраняются |
| Новое `orgName` при прежнем `orgExtId` | Обновляются сведения источника и текущие кадровые атрибуты. Название, заданное администратором, и исторические снимки не переписываются |
| Запрет создания заявок для организации | Новые заявки запрещены. Прежние видны в реестре; работу с существующими черновиками можно продолжить |
| Новое название, категория или срок СИЗ | Новые назначения получают новые значения. Уже сохранённые назначения сохраняют свои значения |
| Снятие «Активна» у позиции | Новое назначение запрещено. Прежнее можно сохранить, завершить с ним заявку или удалить из черновика |
| Удаление используемой организации или позиции | Операция отклоняется, связанные сведения сохраняются |

Предупреждение о повторе использует срок, сохранённый у предыдущего назначения. Изменение сегодняшнего каталога не сокращает и не продлевает задним числом прежний срок. Отсчёт идёт от календарной даты завершения предыдущей заявки.

Отключённые позиции остаются видимыми в сохранённом составе и истории. Если убрать такую позицию из черновика и сохранить, назначить её заново можно только после включения в каталоге. Если справочник меняли, пока интерфейс открыт, перезагрузите страницу после сохранения локальных изменений. Сервер всегда перепроверяет допустимость записи.

## Обновление существующей базы

Миграция `0002_managed_directories` переносит существующие организации из сотрудников и заявок. Она не добавляет готовый перечень организаций или СИЗ. Для организаций с уже существующими заявками сохраняется разрешение на создание новых; остальные записи по умолчанию выключены. На чистой базе записей не создаётся.

Старые данные не содержат `orgExtId`, поэтому миграция не угадывает его по названию. После обновления сопоставьте перенесённые записи через Admin до следующей новой выгрузки 1С. Старые названия остаются снимками, а проверки принадлежности работают по постоянному ID.

У старых назначений не было снимков каталога. Миграция фиксирует доступные на момент перехода название, код, категорию и срок. Если каталог менялся раньше, первоначальные значения нельзя восстановить из прежней схемы; их можно подтвердить только внешними документами или резервной копией.

Переход требует окна обслуживания выбранного контура: [operations.md](operations.md). Откат схемы через `migrate workwear 0001` не поддерживается. Для возврата нужны проверенная резервная копия базы до перехода и соответствующий коммит приложения.
