# Приём справочника 1С

Импорт обновляет справочник сотрудников для Workwear. Интерфейс отдельно показывает дату источника `source_export_date` и время приёма `accepted_at`. Период табеля в контракт не входит.

## Формат источника

CSV в UTF-8 с необязательным BOM используют разделитель `;`. Обязательные колонки перечислены ниже. Дополнительные колонки допустимы, заголовки должны быть уникальны.

| Файл | Обязательные колонки |
|---|---|
| `Employees.csv` | `extId;tabNumber;name;positionExtId;unitExtId;orgExtId;orgName` |
| `Positions.csv` | `extId;name` |
| `Units.csv` | `extId;name;orgExtId;orgName` |

`extId` сотрудника, должности и подразделения — UUID. `orgExtId` — устойчивый ключ организации до 255 символов без пробелов, сохраняется в нижнем регистре. Табельный номер, ФИО и организация сотрудника обязательны. Должность и подразделение могут быть пустыми. Заполненные ссылки должны разрешаться, подразделение сопоставляется по GUID и организации. Одинаковые и дополняющие записи одного GUID объединяются. Конфликтующие заполненные атрибуты отклоняются.

Каждый файл содержит от 1 до 1 000 000 строк данных и занимает до 128 МиБ. Заголовок не входит в лимит строк. Для публикации три обычных CSV должны лежать в корне архива `.tar.gz`. Парсер читает архив без распаковки.

Оборванный архив, ошибки формата CSV и нулевой символ в тексте останавливают проверку до публикации. Повторно выгрузите повреждённый файл из 1С.

## Проверка и публикация

Выполняйте команды из корня проекта в окружении выбранного контура под прикладной ролью. Для DEV это `VEQTA_ENV=dev`, `DB_NAME=veqta_dev`, `DB_USER=veqta_dev`. Храните источники и диагностический вывод вне публичных файлов. В отчёте проверки могут быть GUID.

```bash
tar -czf private/source.tar.gz -C private/source Employees.csv Positions.csv Units.csv
python manage.py workwear_import_1c private/source.tar.gz --environment dev --database-name veqta_dev
```

Сверьте в отчёте `unique_current_employees` и `publication_review`. Для проверки можно передать каталог с CSV. Для публикации используйте уже проверенный архив.

```bash
read -r -p 'Подтверждённое число сотрудников: ' EMPLOYEE_COUNT
read -r -p 'ID последнего принятого импорта, 0 для первого: ' PREVIOUS_IMPORT_ID
read -r -p 'Подтверждённая дата выгрузки YYYY-MM-DD: ' EXPORT_DATE
python manage.py workwear_import_1c private/source.tar.gz --environment dev \
  --database-name veqta_dev --apply --expected-employee-count "$EMPLOYEE_COUNT" \
  --expected-previous-import-id "$PREVIOUS_IMPORT_ID" --source-export-date "$EXPORT_DATE"
```

Если проверка показывает выпавших сотрудников, сначала сверьте список с источником, затем добавьте `--confirm-missing-current-sha256` с хешем из отчёта. Для PROD возьмите параметры и прикладную роль PROD.

## Правила приёма

- Организации сопоставляются по `orgExtId`. Новый идентификатор создаёт запись с выключенным разрешением заявок. При совпадении названия с ручной записью без ID сначала заполните её ID в Admin. `orgName` обновляет служебное название источника. Отображаемое имя ведёт администратор. [Организации](directories.md#организация).
- Новые GUID добавляются. Для известных GUID обновляются ФИО, табельный номер, должность и подразделение. Организация закреплена за GUID. Исчезнувшие сотрудники сохраняются в справочнике и истории. Для нового включения в заявку нужен сотрудник актуальной выгрузки.
- Повтор последней тройки хешей с той же датой возвращает `already_accepted`. Архив с другими хешами допускается в тот же календарный день при точном ID предыдущего импорта. Ранее принятая тройка и источник с более ранней датой отклоняются.
- Число сотрудников, предыдущий импорт и подтверждение выпадений проверяются при публикации. При ошибке весь пакет откатывается. После исправления повторите проверку архива.
