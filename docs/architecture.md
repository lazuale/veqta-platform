# Архитектура

VEQTA — проект Django с отдельной базой PostgreSQL для каждого контура. `config/urls.py` подключает Django Admin, Portal, Workwear и JSON API. Вход, выход и смена пароля используют штатные представления Django. Меню учитывает права пользователя.

| Путь | Ответственность |
|---|---|
| `config/settings.py`, `config/database.py` | Окружение и проверка фактической БД и роли для служебных команд |
| `portal/` | Страницы, шаблоны, навигация и общая статика |
| `workwear/models.py`, `workwear/admin.py` | Модели и штатное ведение справочников |
| `workwear/services.py`, `workwear/sync.py` | Жизненный цикл, атомарное изменение состава и журнал |
| `workwear/eligibility.py`, `workwear/ingest_lock.py` | Проверка актуальности сотрудника и блокировка справочника |
| `workwear/employee_lookup.py`, `workwear/repeats.py` | Разрешение строк массового подбора и расчёт повторов |
| `workwear/api.py`, `workwear/ui_api.py` | HTTP-контракт, сериализация, параметры и ошибки |
| `workwear/importers/directories_1c.py`, `workwear/importers/acceptance.py` | Разбор CSV и транзакционная публикация справочника |
| `workwear/management/commands/` | Инициализация пустой схемы и загрузка данных |
| `workwear/migrations/0001_initial.py` | Окончательная схема, составные FK и триггеры |

## Модели и снимки

| Модель | Данные |
|---|---|
| `Organization` | Внутренний ID, отображаемое имя, внешний ID 1С, название из источника и разрешение новых заявок |
| `EmployeeImport` | Хеши трёх CSV, счётчики, календарная дата выгрузки и время приёма |
| `Employee` | GUID, кадровые атрибуты, неизменяемая организация и ссылка на последний импорт, где сотрудник присутствовал |
| `WorkwearItem` | Неизменяемый код, название, категория, срок в днях, порядок и активность |
| `Request` | Организация и снимок её имени, статус, версия, автор и сведения о завершении |
| `RequestEmployee` | Связь заявки и сотрудника, организация и снимок кадровых атрибутов на момент включения |
| `RequestAssignment` | Связь участника и позиции, снимок кода, имени, категории и срока |
| `WorkwearEvent` | Номер заявки, автор, время, тип и детали события. История сохраняется после удаления черновика |

PostgreSQL заполняет `snapshot_*` при вставке, включая `bulk_create`. Заявка сохраняет название организации при создании, участник — кадровые данные при добавлении. История не меняется после обновления справочников. Повторную выдачу рассчитывает `repeats.scan_repeats` по закрытым заявкам и сроку предыдущего назначения. [Правила для аналитика](workwear.md).

Модели и таблицы названы по соглашениям Django. JSON использует `snake_case`; поля 1С, например `orgExtId`, остаются на границе импорта. SQL-объекты Workwear имеют префикс `ww_`. [Контракт 1С](import-1c.md).

## Транзакции и права

При изменении заявки сервис проверяет права, берёт разделяемую advisory-блокировку справочника, затем блокирует заявку через `SELECT FOR UPDATE`. Под блокировкой сверяется версия. Изменения и история сохраняются одной транзакцией. Импорт берёт исключительную блокировку того же ключа, поэтому новые включения проверяются по последней принятой выгрузке.

Отдельные изменения выполняет `services.py`. Редактор отправляет весь черновик в `sync.py`; сервер сохраняет только различия. При `finish=true` завершение входит в ту же транзакцию. Все HTTP-маршруты используют сессию Django и CSRF. [Права аналитиков и администраторов](workwear.md#доступ).

## Инварианты PostgreSQL

| Защита | Правило |
|---|---|
| `ww_member_req_org_fk` и `ww_member_emp_org_fk` | Организация заявки, участника и сотрудника совпадает |
| `ww_guard_employee_identity`, `ww_guard_organization_identity`, `ww_guard_item_identity` | Идентичность сотрудника, установленный внешний ID организации и код позиции неизменяемы |
| `ww_guard_request_insert` и `ww_guard_request_identity` | Новая заявка создаётся для разрешённой организации как черновик версии 1 и сохраняет происхождение |
| `ww_guard_member_write` и `ww_guard_assignment_write` | Снимки неизменяемы. Новые записи проверяют актуальность сотрудника или активность позиции. Закрытый состав защищён |
| `ww_guard_request_lifecycle` | Контролирует версию, полноту завершения, поля статуса и запрет удаления закрытой заявки |
| `ww_reject_event_change`, `ww_reject_structure_truncate` | История доступна только для добавления. TRUNCATE защищённых таблиц отклоняется |
| FK, UNIQUE и CHECK Django | Ссылки, уникальность GUID, кодов, участников и позиций, допустимые сроки и обязательные поля |

Начальная миграция Workwear создаёт 10 функций с `SECURITY INVOKER`, 13 триггеров и два составных FK. SQL-контроль целостности действует на любые записи. Права конкретного пользователя проверяет сервис Django.

В каждом контуре `veqta_ENV_owner` владеет схемой и применяет миграции. Прикладная роль `veqta_ENV` получает права на соединение, схему, данные, последовательности и функции. Права по умолчанию задаются до миграций. Для владельца глобально отозван `EXECUTE` у `PUBLIC`; владельцу DEV разрешён `CREATEDB` для тестов. [Развёртывание и права ролей](deployment.md).

## HTTP API

Страница доступна по `/workwear/`, API — по `/workwear/api/`. Точные параметры описаны у представлений в `workwear/api.py` и `workwear/ui_api.py` и проверяются тестами. Записывающие запросы передают `application/json` и CSRF, а изменения существующей заявки — `expected_version`.

| Маршрут относительно API | Назначение |
|---|---|
| `session/` | GET имени вошедшего пользователя и токена CSRF |
| `requests/` | GET краткого списка до 50 записей, POST нового черновика по `organization_id` |
| `requests/<id>/` | GET всей заявки со снимками, DELETE черновика |
| `requests/<id>/members/` и `requests/<id>/assignments/` | POST отдельного включения и назначения |
| `requests/<id>/members/<member_id>/` и `requests/<id>/assignments/<assignment_id>/` | DELETE отдельного участника и назначения |
| `requests/<id>/complete/` и `requests/<id>/reopen/` | POST завершения и возврата |
| `ui/metadata/` | GET справочников, даты импорта, прав и технических лимитов |
| `ui/requests/` и `ui/employees/` | GET реестра и поиска с пагинацией до 100 и 40 строк соответственно |
| `ui/resolve/` | POST массового подбора до 100 строк |
| `ui/requests/<id>/bulk-add/` | POST одновременного включения нескольких сотрудников в сохранённый состав |
| `ui/requests/<id>/sync/` | POST полного состава `members`, версии и флага `finish` |
| `ui/requests/<id>/repeat-scan/` | POST проверки до 1200 пар сотрудник–позиция |
| `ui/requests/<id>/events/` и `ui/requests/<id>/employees/<employee_id>/history/` | GET журнала и истории назначений сотрудника |
| `ui/requests/<id>/reopen/` | POST возврата. Поле `reason` принимает строку до 500 символов, в том числе пустую |

Метаданные различают `organizations` для новых заявок и `registry_organizations` для фильтра всех заявок. Каталог в метаданных зависит от `view_workwearitem`. Снимки назначений читаются вместе с заявкой.

Для массового подбора интерфейс передаёт весь текущий состав черновика в `present_employee_ids`, включая пустой список. При запросе с `request_id` без этого поля состав читается из сохранённой заявки.

Бюджет обычного JSON — 64 КиБ, для `sync` — 1 МиБ. Ошибки параметров дают 400, сессии 401, доступа или CSRF 403, отсутствия объекта 404, метода 405, версии или целостности 409 и превышения размера 413. JSON-ошибки приложения содержат код и сообщение.

## Интерфейс Workwear

`workwear/static/workwear/app.js` подключает нативные ES-модули. `core.js` владеет состоянием страницы `settings`, HTTP, снимком сервера и служебными функциями. `registry.js` ведёт фильтры и URL, `editor.js` — локальный состав и сохранение, `employees.js` — подбор, `overlays.js` — диалоги и историю, `paging.js` — страницы, `batching.js` — ограниченные параллельные чтения. `controller.js` связывает делегированные события с функциями этих модулей. Точка входа подключает модули до запуска контроллера. Модули получают готовые функции при подключении. Вызовы между реестром, редактором и диалогами, которые зависят от порядка сборки, идут через контекст уже при обработке действия.

Сохранение передаёт весь нормализованный состав. Локальные действия обновляют затронутые строки и восстанавливают фокус и прокрутку. Страницы матрицы ограничивают объём DOM, сохраняя выбранный набор и записи черновика. Матрица использует HTML-таблицу с `colgroup`, `scope`, `headers` и одним доступным через Tab элементом ячейки. Индекс позиций строится по метаданным и подтверждённому снимку. Каждое назначение использует собственные снимки, а заголовок колонки — текущий каталог. Счётчики запросов и `AbortController` не дают поздним ответам менять новый экран.

`portal/templates/portal/base.html` задаёт порядок стилей `tokens.css`, `base.css`, `components.css`, `layout.css` и `portal.css`. Workwear добавляет `app.css`. Компоненты используют токены Portal и локальную статику. Nginx требует перепроверки кеша после обновления.
