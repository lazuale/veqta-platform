# Проверки проекта

Тесты используют только синтетические имена, номера и случайные GUID. Они создают отдельную PostgreSQL `test_veqta_dev`. Кадровые выгрузки и утверждённый рабочий каталог в тестах не используются.

## Регрессионный набор

Из корня проекта с активным venv и загруженным `.env.dev`:

```bash
python -m pip install --require-hashes -r requirements.lock
python -m pip check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test tests --verbosity 2
```

Штатный Django TestCase откатывает транзакцию каждого теста. Защитные триггеры остаются включёнными. Не используйте flush и не отключайте TRUNCATE-защиту ради очистки тестов. Рабочие veqta_dev и veqta_prod не очищаются тестовым набором.

Временная тестовая база удаляется по завершении. Не сохраняйте в ней свои данные и не используйте --keepdb. Если предыдущая проверка аварийно оборвалась, сначала отдельно проверьте, что оставшаяся test_veqta_dev относится именно к тестам; только затем удаляйте её штатными средствами PostgreSQL.

## Конкурентное редактирование

```bash
python -m tests.acceptance
```

Проверка создаёт тестовую схему и запускает две отдельные транзакции с одной ожидаемой версией. Ровно одна запись должна пройти, другая — получить конфликт. Затем проверяются версия, состав и число событий. Существующую test_veqta_dev эта команда не перезаписывает.

## Браузер

Дополнительные зависимости нужны только для испытаний интерфейса:

```bash
python -m pip install --require-hashes -r requirements-browser.lock
python -m playwright install chromium
python -m tests.acceptance --browser
```

При наличии подходящего установленного браузера можно явно указать путь:

```bash
python -m tests.acceptance --browser --browser-executable /usr/bin/chromium
```

Playwright запускает временный сервер только на loopback и в тестовой базе. Пользователь и пароль создаются на время проверки; они не записаны в исходниках. Проверяются вход, переход в Workwear, создание черновика, массовый подбор, назначение СИЗ, сохранение, матрица, завершение, возврат и экран шириной 390 px. Ошибки JavaScript и неуспешные HTTP-ответы приводят к отказу проверки.

| Сравнение конечной схемы с исходной цепочкой миграций | Точное совпадение каталога PostgreSQL и pg_dump схемы |
| Функции и триггеры Workwear | 8 функций, 11 триггеров сохранены |
| Автоматические проверки | 64 теста пройдены |
| 1000 сотрудников, 30000 назначений | Сохранение и завершение пройдены; 50 SQL-запросов |
| Атомарность ошибок и защита завершённых заявок | Проверены сервисами и прямым SQL |
| Одновременная запись одной версии | Одна успешная запись, один конфликт |
| Команды загрузки каталога и 1С в DEV и PROD | Dry-run, приём и повторный приём проверены внутри откатываемой транзакции |

| Проверка типов и содержимого публикуемых файлов | Выполняется перед упаковкой, секреты и рабочие выгрузки не включаются |

Размер 30000 относится к техническому тесту с 30 вымышленными позициями. Это не изменение утверждённого рабочего каталога из 11 позиций. Время выполнения зависит от машины; измерения локального теста не являются гарантией производительности сервера.

Сравнение миграций выполнено на отдельных пустых базах: исходная цепочка и новая начальная миграция. Сверены столбцы, типы, значения по умолчанию, ограничения, внешние ключи, индексы, последовательности, функции, определения триггеров и штатные разрешения. Дамп схемы совпал после исключения случайного служебного токена pg_dump. Данные не переносились, --fake не использовался.

Для локального HTTPS использовался временный сертификат с явным доверием тестового клиента. Сертификат и ключ в проект не включены. Сертификат вашего домена и запуск unit systemd на целевом узле — **Не проверено**: доступа к этому узлу в локальной сборке нет. Firefox, WebKit и полный аудит доступности — **Не проверено**: проверялся Chromium и указанный сценарий.

## Проверка после установки

Войдите обычным аналитиком и проверьте права по таблице в workwear.md. Просмотр всех организаций должен оставаться доступным, а включение сотрудника чужой организации — отклоняться. Проверьте выход, смену пароля штатной формой, конфликт двух вкладок и запрет правок завершённой заявки. После получения утверждённого CSV отдельно проверьте рабочие названия и сроки 11 позиций; синтетический тест этого не подтверждает.
