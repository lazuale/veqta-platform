# Загрузка каталога и справочников 1С

Все команды запускаются из корня проекта с активным venv и загруженным окружением. Примеры ниже относятся к DEV. Для PROD одновременно замените окружение, роль и явные параметры на prod / veqta_prod.

## Каталог СИЗ

Каталог не является кадровой выгрузкой. Утверждённого CSV в исходном приложении нет; автоматически создавать названия, коды, категории или сроки нельзя. Владелец процесса должен предоставить утверждённые 11 позиций. Без него рабочий каталог после миграций пуст.

CSV: UTF-8 с необязательным BOM, разделитель `;`, ровно шесть колонок:

```text
code;name;category;validity_days;sort_order;is_active
```

| Поле | Условие |
|---|---|
| `code` | Непустой уникальный код, до 32 символов |
| `name` | Утверждённое название, до 120 символов |
| `category` | Утверждённая категория, до 64 символов |
| `validity_days` | Только 365 или 730 |
| `sort_order` | Целое число от 0 |
| `is_active` | 0 или 1 |

Сохраните CSV вне исходников либо в исключённом каталоге `private/`:

```bash
python manage.py workwear_load_catalog private/approved_catalog.csv --environment dev --database-name veqta_dev
python manage.py workwear_load_catalog private/approved_catalog.csv --environment dev --database-name veqta_dev --apply
```

По умолчанию команда лишь проверяет файл. При apply она создаёт недостающие записи одной транзакцией; совпадающие сохраняет, конфликтующие не перезаписывает. Число входных строк по умолчанию равно 11. `--expected-count` предназначен для отдельно согласованного изменения каталога; его нельзя использовать для обхода требования 11 рабочих позиций.

## Контракт 1С

Используются только три файла: `Employees.csv`, `Positions.csv`, `Units.csv`. Кодировка UTF-8 с необязательным BOM, разделитель `;`. Дополнительные колонки допускаются, обязательные заголовки не должны повторяться. Не используйте кадровые файлы в качестве тестовых примеров или содержимого репозитория.

| Файл | Обязательные колонки |
|---|---|
| `Employees.csv` | `extId;tabNumber;name;positionExtId;unitExtId;orgExtId;orgName` |
| `Positions.csv` | `extId;name` |
| `Units.csv` | `extId;name;orgExtId;orgName` |

`extId` сотрудника, должности и подразделения — UUID. `orgExtId` в текущем адаптере — непустой идентификатор организации; его формат UUID не навязывается. `tabNumber`, имя и организация сотрудника обязательны. Пустые ссылки на должность или подразделение допустимы и отражаются в счётчиках. Непустые ссылки должны разрешаться. Подразделение ищется по паре GUID и организация. Конфликтующие непустые атрибуты одного GUID отклоняются; одинаковые и дополняющие строки объединяются.

Один файл ограничен 128 МиБ, число строк — установленным в адаптере пределом порядка миллиона. Архив читается без распаковки: три CSV должны лежать непосредственно в корне tar.gz, быть обычными файлами и не повторяться. Символические ссылки и вложенные пути не используются.

## Приём справочника

Сначала проверьте каталог файлов без записи:

```bash
python manage.py workwear_import_1c private/source --environment dev --database-name veqta_dev
```

Изучите `unique_current_employees`, а также `publication_review`: предыдущий импорт, количество выпавших GUID и их SHA-256. Эти результаты могут содержать кадровые идентификаторы; не публикуйте их в исходниках или общедоступных журналах.

Для приёма нужен неизменяемый снимок:

```bash
tar -czf private/source.tar.gz -C private/source Employees.csv Positions.csv Units.csv
python manage.py workwear_import_1c private/source.tar.gz --environment dev --database-name veqta_dev
```

Заполните параметры по фактическому dry-run и подтверждённой дате выгрузки, затем примите пакет. Значение 0 для предыдущего импорта означает только первое принятие:

```bash
read -r -p 'Подтверждённое число сотрудников: ' EMPLOYEE_COUNT
read -r -p 'ID последнего импорта, 0 для первого: ' PREVIOUS_IMPORT_ID
read -r -p 'Дата выгрузки ISO8601 с часовым поясом: ' EXPORTED_AT
python manage.py workwear_import_1c private/source.tar.gz --environment dev --database-name veqta_dev --apply --expected-employee-count "$EMPLOYEE_COUNT" --expected-previous-import-id "$PREVIOUS_IMPORT_ID" --source-exported-at "$EXPORTED_AT"
```

Если сотрудники выпадают из текущей выгрузки, передайте дополнительно `--confirm-missing-current-sha256` с точным digest из проверенного dry-run. При предыдущем импорте без даты требуется явное `--acknowledge-undated-previous`. Не добавляйте эти параметры без проверки причины.

Публикация блокирует справочник и выполняется одной транзакцией. Новые GUID добавляются, существующие обновляют имя, табельный номер, должность и подразделение. Исчезнувшие сотрудники не удаляются, но новое включение в заявку им недоступно. Смена организации без нового GUID отклоняется. Снимки ранее созданных заявок не переписываются.

Повтор последней тройки хешей с той же датой возвращает already_accepted без нового импорта. Более старая уже принятая тройка и дата, не новее последней принятой, отклоняются. Дата приёма не заменяет дату источника. Период табеля из этих трёх справочников не выводится: даты охвата остаются NULL.

При ошибке количества, версии справочника, ссылок или SQL-ограничения весь apply отменяется. Исправьте источник или подтвердите правильный снимок и повторите dry-run. Отключать триггеры и исправлять рабочие таблицы напрямую не требуется.
