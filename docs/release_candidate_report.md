# Приёмка VEQTA Release Candidate

Дата: 17 ноября 2026, Europe/Moscow. Результат — проверенный локальный RC. Серверное переключение и промышленная приёмка не выполнялись.

Исходный `main`: `36a2f52dd737cda96f91f437d46c85a500d9a629`. Проверенный итоговый код и тесты: [`d27134363a7997965b4b180f03fc6eed1e222720`](https://github.com/lazuale/veqta-platform/commit/d27134363a7997965b4b180f03fc6eed1e222720). Следующий коммит добавляет этот отчёт и согласованные инструкции; исполняемый код в нём не меняется. Полный итоговый HEAD фиксируется в выданном архиве результатов и истории Git.

## Изменения кода

Удалены подтверждённые остатки прежнего интерфейсного кода:

- Одиночный `editor.addLocal` и его экспорт: все действующие включения используют атомарный локальный `addLocals`.
- Неиспользуемые локальные обёртки `controller.addLocal`, `controller.cell`, `employees.addLocal`, `overlays.memberVisible`, `editor.assignments`.
- Параметр `groups(activeOnly)` и ветвь фильтрации: вызывающие модули не передавали аргумент.
- Параметр `save(leave)`, его недостижимая ветвь выхода и обёртка `editor.openRegistry`. Реальный выход после сохранения остаётся в контроллере через `finishRoute` и проверен браузером.
- Неиспользуемый импорт `sys` в приёмке после выделения общего временного сервера.

Проверены вызовы через общий JavaScript-контекст, делегированные обработчики, Django URL, шаблоны, команды, тесты и документацию. Python AST не показал других неиспользуемых импортов; `from __future__ import annotations` сохранён. Маршруты действующего API не удалялись только из-за отсутствия вызова из текущей страницы. Повторные CSS-правила для каскада, состояний и адаптивности сохранены. Это перечень доказанных удалений, а не обещание отсутствия любого возможного технического долга.

Доступность ячейки сведена к одной проверке для отображения и клавиатуры. Заголовки групп теперь строятся по соседним колонкам. Нормализация Tab-фокуса выполняется при реальном фокусировании и после замены строки. Общий запуск временного сервера вынесен в `tests/browser_support.py`; синхронные проверки PostgreSQL из Playwright выполняются в отдельном потоке без отключения защиты Django от ORM в asyncio.

Модели, сервисные транзакции, авторизация, импорт и начальная миграция сохранены. Организации и каталог остаются данными PostgreSQL. Пользователи, группы и разрешения управляются штатным Django Admin. Прямое редактирование заявок и событий через Admin не открыто.

## Реальная приёмка матрицы

Chromium Headless Shell 156.0.8078.79, Playwright 1.62.0, Django 6.1.3, Python 3.14.4, PostgreSQL 18.7. Временный сервер и все базы находились в изолированной локальной среде. Использовались только вымышленные имена, GUID, организации и позиции.

Основной набор: 210 сотрудников, 62 позиции, перемежающиеся категории, сроки 90/365/730 дней, отключённая позиция с прежним назначением, пустая строка и предыдущее завершённое назначение. Сверены пары сотрудник/позиция между PostgreSQL и API, `aria-pressed` всех 3000 видимых ячеек и суммы строк. После сохранений проверены точные пары, после перезагрузки — восстановленное состояние.

Все 10 групп прошли. `matrix-results.json` содержит `completed=true`, `passed=true`, версию браузера, результаты сценариев и ожидаемые/фактические HTTP-ошибки. Неожиданных HTTP-ошибок и исключений JavaScript нет. Четыре сообщения console.error относятся к намеренно вызванным 500, двум обрывам сети и 409; предупреждений браузера нет.

DOM проверен по идентичности узлов: при изменении одной ячейки основной контейнер, таблица и незатронутая строка остаются прежними. Фокус восстанавливается в затронутой строке. Между режимами сохраняется логический черновик; серверные данные меняются только после подтверждённого сохранения.

История предыдущих назначений открыта через карточку и просмотр старой заявки. Журнал created/draft_synced/completed/reopened проверен через API и PostgreSQL. Отдельного экрана журнала событий в текущем UI нет; API-проверка не выдаётся за проверку такого экрана.

## Производительность

Однократные замеры последнего подтверждающего прогона, секунды. Это локальная приёмка, без эмуляции медленной сети и без параллельных пользователей. Открытие измеряется до готовности списка, переход к матрице — до отрисовки и окончания проверки повторов. Массовое снятие выполняется у всех показанных сотрудников: до 100. Для 1000×30 браузер отправил 55 API-запросов: session и metadata по одному, GET состава дважды, один sync и 50 пакетов repeat-scan — 25 при открытии и 25 после записи. Переходы режима/страницы и массовое снятие не загружают состав повторно. Полные количества по маршрутам сохранены в JSON. Контрольные чтения через APIRequestContext не входят в счётчик сетевых запросов страницы. С исходной backend-метрикой эти времена не сравниваются: измеряется другой участок работы.

Отдельный регрессионный тест сохранил и завершил 1000×30 за 1.61 с и 50 SQL-запросов. Предыдущий отчёт чистой схемы показывал 1.55 с и те же 50 запросов. Одиночные замеры не доказывают регрессию от разницы 0.06 с. Подтверждённого узкого места, требующего смены пагинации или инфраструктуры frontend, не найдено.

## PostgreSQL, Cold Start и остальные проверки

Новый отдельный кластер прошёл `tests.coldstart`: одна `workwear.0001_initial`, отсутствие предметных записей после migrate, 10 SQL-функций, 13 включённых триггеров, два составных FK, окончательные поля без старых дубликатов. Затем выполнены createsuperuser, вход, штатные формы справочников, DRY_RUN/APPLY CSV-архива через команду импорта и первая завершённая заявка. Проверки migrate и makemigrations не обнаружили расхождений.

Все 111 Django-тестов прошли за 7.051 с. Включены прямые SQL-проверки закрытых заявок, идентичности, снимков, истории, TRUNCATE, составных FK и принадлежности к последней выгрузке; транзакционные тесты проверяют откат при сбое аудита и исключении пустых участников. Отдельный конкурентный сценарий дал ровно одно сохранение и один конфликт, без частичных записей.

Короткая браузерная приёмка прошла вход, Portal, профиль, нативную смену пароля, создание/подбор/назначение/сохранение/завершение/возврат. Через настоящие формы Admin созданы организация, позиция, пользователь и группа; назначено штатное разрешение, проверен отдельный вход читателя. Пустые справочники дают объяснённые недоступные действия. Технические модели не открыты для прямого редактирования.

Прошли `pip check`, проверка состава исходников, компиляция Python, синтаксис всех JavaScript-модулей и `git diff --check`. Начальная миграция и рабочие DEV/PROD не менялись.

## Ограничения приёмки

Firefox и WebKit отсутствуют в доступной установке Playwright; прогоны этих движков не выполнены. Не выполнены испытания настоящих мобильных устройств, screen reader, полная проверка WCAG, реального масштаба браузера и всех сочетаний клавиш на всех ОС. Шесть размеров viewport и работа клавиатуры в Chromium проверены непосредственно.

Замеры относятся к одному локальному пользователю, loopback и Django runserver. Не проверены промышленная многопользовательская нагрузка, Nginx/systemd на целевом сервере, аварийное восстановление, новая установка ОС и переключение работающих контуров. Миграция старой базы в новую схему не входит в Cold Start. Подтверждённых незакрытых дефектов из выполненных сценариев нет; готовность к промышленной эксплуатации этим отчётом не объявляется.
